# PadelLabs-ML — Stroke Classifier Workflow (Agent Guide)

This document is the **single source of truth** for the Claude agent operating in
the `PadelLabs-ML/` directory. It defines the end-to-end pipeline for preparing
new recorded sessions, labeling them against video, integrating the labels into
the training set, and bumping the stroke classifier to a new version.

> **Read this first.** When the user says "prepare this session for labeling",
> "train the next version", or similar, follow the stage that matches and do not
> invent steps. Every script below already exists — do not rewrite them.
>
> **For "what's next" / the v6 plan, read `V6_ROADMAP.md`** — it captures the current
> shipped state (v5 RF on Firebase), the full investigation conclusions (player diversity
> is the blocker; RF is at its order-invariant ceiling; the temporal CNN overfits at 6
> players), the recording enrichment shipped (gravity+quaternion columns), and the exact
> step-by-step playbook + tooling/venv gotchas to execute once more players are collected.
>
> **2026-07-11 sweep (see the roadmap table):** IMU augmentation (~2× raw CNN),
> gravity+aug (no stack), SSL pretraining (null — unlabeled pool has no new players)
> all tested with a multi-seed protocol. CNN plateau ≈ 19–20% vs RF 37.5% on unseen
> players — model-side levers are exhausted at this corpus; collect players next.

## 2. Stage 1 — Per-session preparation (before labeling)

**Trigger**: user hands a raw session (`<sessionId>.csv` + `.json`) and says
"classify this with v<N>" or "prepare this for labeling".

**Goal**: produce a `<sessionId>_classified.csv` that the web labeling tool can
auto-pair with the raw JSON, with **every** stroke visible to the reviewer.

### 2.1 Run the classifier

```bash
python3 scripts/classify_session.py \
    --session "/path/to/<sessionId>.csv"
```

Behaviour to know:
- The script retrains a RandomForest at runtime from `labeled-strokes/train/`
  with leave-one-session-out (excludes the target session from training for
  honest accuracy). This is equivalent to the currently-shipped model version
  because training data + seed are identical.
- Output filename is hardcoded `<sessionId[:8]>_v2_classified.csv` regardless
  of the actual version being evaluated — **you must rename it afterwards** to
  `<sessionId[:8]>_v<N>_classified.csv` to preserve version history.
- Burst-grouping (1.2 s gap) and preparation-spike dedup run automatically.

### 2.2 Convert to tool-ready classified.csv

The labeling tool (`labeling-tool/index.html`) has two hard requirements that
the raw classifier output does NOT satisfy:

1. Filename must be `<full sessionId>_classified.csv` (full UUID, not the 8-char prefix)
2. Only rows with `above_threshold=yes` load into the tool

Since the user wants to validate **every** stroke (not just confident ones),
post-process the file:

```python
# Transform <sessionId[:8]>_v<N>_classified.csv → <sessionId>_classified.csv
# 1. Set every row's above_threshold = "yes"
# 2. Set predicted_stroke = top1 (so low-confidence rows still show a guess, not "unknown")
# 3. Preserve all other columns (timestamp_s, confidence, top1/top2/top3 + their conf)
```

The tool will then expose all 500-1000+ strokes for video-based validation,
with top-3 alternatives and confidence bars shown per row.

### 2.3 Keep both files

- Keep `<sessionId[:8]>_v<N>_classified.csv` as a diagnostic/reproducibility
  reference (shows the model's actual thresholded output).
- The `<sessionId>_classified.csv` is the one loaded by the labeling tool.

## 3. Stage 2 — Labeling via the web tool

**Who does this**: the user, not Claude. Document the workflow so the agent can
support it (generate files, explain steps) but never auto-validate.

**Workflow**:
1. User opens `labeling-tool/index.html` in a browser.
2. Loads the session folder (drag-drop or File System Access API) — the tool
   auto-pairs the JSON + `_classified.csv`.
3. Loads the matching video from `labeling-tool/videos/<Player>/<clip>.MOV`.
4. Clicks **Validate**, then **⚡ Auto-accept** (active-learning triage):
   every pending prediction with `confidence ≥ 0.85` AND `top1 − top2 ≥ 0.30`
   is marked `correct` automatically (thresholds tunable inline; one-click
   **↩ Undo auto**; a human verdict always overrides an auto one). Cuts a
   ~800-stroke session to ~200 manual reviews — and the remaining queue is
   exactly the low-confidence lob/vibora/bandeja cases the model needs most.
5. Walks through the remaining strokes:
   - Tool seeks video to `timestamp_s - 0.5s`
   - Shows top-3 predictions with confidence bars
   - User marks `correct` / `wrong` (+ picks true label) / `skip` / `duplicate`
6. User clicks **Export** → tool saves `<sessionId>_validation.csv` back to the
   session folder. The CSV carries a trailing `review_mode` column
   (`auto`/`manual`) for provenance; `apply_validation.py` reads columns by
   name and is unaffected.

> First-time calibration: on the first session using auto-accept, spot-check
> ~20 auto-accepted rows before trusting the thresholds at scale.

**Reference implementation in the wild**: the Jose 21 April session under
`/DataCollection/Jose full sessions strokes/21 April/` is the canonical example
of a completed Stage 2 output (`*_validation.csv`).

## 4. Stage 3 — Integrate a validated session into the training set

**Trigger**: user says "this session is validated, add it to training" or "pull
the Ela 23 April session into labeled-strokes".

### 4.1 Prerequisites before integration

- [ ] `<sessionId>_validation.csv` exists in the session folder with filled
      `verdict` and (where applicable) `corrected_label` columns.
- [ ] Player is registered in `metadata/players.csv`. If missing, add a row
      (playerId, displayName, handedness, watchWrist, skillLevel).
- [ ] Session is **not** already present in `labeled-strokes/metadata.csv`.

### 4.2 Extract windows

`scripts/extract_windows.py` turns raw CSVs + JSON markers into per-stroke
window CSVs (100 samples each: 30 pre-peak + 70 post-peak):

```bash
python3 scripts/extract_windows.py \
    --sessions  ../DataCollection \
    --output    ./labeled-strokes
```

- Reads every `<sessionId>.json` under the `--sessions` tree, applies burst-grouping,
  writes one window CSV per stroke into `labeled-strokes/<split>/<stroke_type>/`.
- Updates `labeled-strokes/metadata.csv` with a row per window.
- `--val-players` / `--test-players` flags route specific players into the val/test splits.

### 4.3 Apply validation corrections

The default extraction uses the marker's `strokeType` directly. To apply the
video-validated corrections from a `_validation.csv`, the session JSON's
marker `strokeType` must be updated first (no script does this automatically
today — if needed, write a one-off patch that walks the validation CSV and
rewrites the JSON markers, then re-run `extract_windows.py`).

Alternatively, use `scripts/cluster_unknowns.py --apply` — it accepts a
`cluster_summary.csv` with corrected labels and writes them back into the
session JSON.

### 4.4 Verify the integration

After extraction, check:
- `labeled-strokes/metadata.csv` has new rows for the session
- Per-class window counts in `labeled-strokes/train/<class>/` went up
- `metadata/sessions.csv` has a row for the session (add manually with the
  counts from `extract_windows` summary table if missing)

## 5. Stage 4 — When to retrain (version bump policy)

**Do not retrain after every session.** The RF model benefits from batch
updates that increase both volume and diversity.

**Bump criteria — bump to v(N+1) only when ALL hold:**

1. **Volume**: `labeled-strokes/train/` has grown by **≥ 500 new windows**
   since the last shipped version (check `models/v<N>/...json` → `n_train_samples`).
2. **Diversity**: at least one of:
   - a new player has ≥ 100 windows across ≥ 3 stroke classes, OR
   - an existing class with < 250 windows in v<N> now has ≥ 100 additional windows.
3. **Split health**: `validation/` and `test/` each still contain ≥ 1
   player NOT in train (player-independent eval preserved).
4. **No regression risk**: `scripts/evaluate_cv.py` shows player-GroupKFold
   accuracy ≥ the v<N> baseline on shared classes.

Between bumps, run ad-hoc evaluations only — never upload.

## 6. Stage 5 — Retrain, evaluate, ship

### 6.1 Retrain

```bash
python3 scripts/retrain.py --output-version v<N+1>
```

Produces:
- `models/v<N+1>/PadelLabs-StrokeClassifier-v<N+1>.mlmodel`
- `models/v<N+1>/PadelLabs-StrokeClassifier-v<N+1>.json` (classes + class_distribution + n_train_samples)

### 6.2 Evaluate honestly

Run all three in order, save outputs:

```bash
# (a) Cross-validation — three flavours (stratified, session-GroupKFold, player-GroupKFold)
python3 scripts/evaluate_cv.py --n-estimators 300 > models/v<N+1>/cv_report.txt

# (b) Held-out test evaluation
python3 scripts/evaluate.py \
    --test ./labeled-strokes/test \
    --model models/v<N+1>/PadelLabs-StrokeClassifier-v<N+1>.mlmodel \
    > models/v<N+1>/test_report.txt

# (c) Session-level sanity check on the most recently validated session
python3 scripts/classify_session.py --session <recent_session.csv>
```

### 6.2.1 v<N> → v<N+1> baseline comparison (canonical recipe)

For the evaluation_report.md "regression vs prior version" section, run
`evaluate.py` against the **same** held-out test set for both the new model
and the previously shipped model. This is the only apples-to-apples comparison
that's reproducible after retrain (per-session `classify_session.py` outputs
drift as `labeled-strokes/train/` grows, so they're not a stable baseline).

```bash
# v<N> baseline on the post-v<N+1> test set
python3 scripts/evaluate.py \
    --test ./labeled-strokes/test \
    --model models/v<N>/PadelLabs-StrokeClassifier-v<N>.mlmodel \
    > models/v<N+1>/test_report_vs_v<N>.txt
```

Diff `models/v<N+1>/test_report.txt` vs `models/v<N+1>/test_report_vs_v<N>.txt`
for the regression-check signal. The test split must not include any session
that's in the v<N+1> train split (player-independent eval — see §8.7).

> ⚠️ **Do not rely on `classify_session.swift` for a frozen v<N> baseline.**
> As of 2026-05-15 the Swift script is out of sync with the v3 model schema:
> it passes features as `f0..f89` and uses different per-channel statistics
> (`zcr` instead of `totalVar`, missing `peakPos` and the four temporal
> features). Fix before relying on it as a baseline source — or use `evaluate.py`
> on the shipped `.mlmodel` as above, which always loads the exact frozen
> model byte-for-byte.

### 6.3 Append to evaluation_report.md

Add a new section to `models/evaluation_report.md` with:
- Version bump date
- `n_train_samples` delta vs previous version
- Player-GroupKFold accuracy (the most honest metric)
- Per-class recall table
- Top 3 confusions
- Any regressions vs the previous version (if any — block ship until addressed)

### 6.4 Ship

Only after evaluation passes the regression check in Stage 5:

```bash
python3 scripts/upload_model.py --version v<N+1>
```

This uploads the `.mlmodel` to Supabase Storage (private bucket), generates a
1-year signed URL, and prints the Firebase Remote Config values to set
(`ml_stroke_model_version`, `ml_stroke_model_url`). See `DYNAMIC_MODEL_UPDATE.md`
for the full end-to-end story including Firebase wiring.

## 8. Data-hygiene rules (hard rules — do not break)

0. **Verify `playerId` uniqueness across physical players before extraction.**
   Data collection sessions are often recorded under a single iOS account for
   speed (no per-player onboarding), which means the JSON's `playerId` reflects
   the **account**, not the **player**. The folder name under `DataCollection/`
   is the ground truth for which physical player a session belongs to. A bulk
   extraction blindly trusting `json.playerId` will lump multiple physical
   players under one ID, breaking player-GroupKFold splits and the §8.7
   left-handed representation rule. Before running `extract_windows.py` on a
   batch of new sessions:

   ```bash
   python3 -c "
   import json, glob
   m={}
   for jp in glob.glob('DataCollection/**/*.json', recursive=True):
       try: d=json.load(open(jp)); m.setdefault(d.get('playerId'),[]).append(jp.split('/')[1])
       except: pass
   for pid, folders in m.items():
       distinct = set(folders)
       if len(distinct) > 1: print(f'COLLISION {pid[:8]}: {sorted(distinct)}')
   "
   ```

   For each collision: pick ONE folder per `playerId` to keep on the original
   ID (typically the player whose data is already in `labeled-strokes/`).
   Patch every other folder's session JSONs to a fresh UUID and add a row to
   `metadata/players.csv`. Reference patches (2026-05-15):
   - `Irene/088E0FD9-...json` → new ID `863A5EC0-...` (was sharing with Ela)
   - `Diego/6E98CE75-...json` → new ID `5E354AD0-...` (was sharing with Jose)
   - `Victor Sessions/184C1BF7-...json` → new ID `14A0FF96-...` (was sharing with Jose)
   - `Guillermo Left Handed/*/*.json` (2 files) → new ID `1880202A-...` (was sharing with Jose)

1. **Never** write raw DataCollection files into `labeled-strokes/` by hand —
   always go through `extract_windows.py` so `metadata.csv` stays consistent.
2. **Never** move a session between splits once integrated without running
   `split_sessions.py` — it refuses to act if splits are inconsistent.
3. **Never** retrain on the union of train+val+test. The split is the
   evaluation contract.
4. **Never** upload a model that regressed on player-GroupKFold accuracy vs
   the previous shipped version without explicit user approval.
5. **Always** bump the version integer (v3 → v4, never v3.1) — the Firebase
   Remote Config key is an integer comparison on the app side.
6. **Always** preserve `_v<N>_classified.csv` diagnostic files after renaming;
   they serve as the evaluation record for that session at that version.
7. **Left-handed / non-dominant-wrist players** must be represented in val +
   test — `split_by_player.py` enforces this but manual splits must respect it.

## 10. Open gaps (known tech debt)

- **`playerId` reflects the iOS account used for recording, not the physical
  player.** Sessions are often captured under a single account to skip
  per-player onboarding, so the JSON's `playerId` collides across distinct
  players whenever the same account records multiple people. The
  `DataCollection/<Folder>/` name is the ground truth — that's the field to
  trust. Existing `labeled-strokes/metadata.csv` is clean (as of 2026-05-15
  it contains only Jose under `E168B6E8-...` and Ela under `3FF5CBC3-...`;
  the other folders' sessions have not been extracted yet). To keep it clean,
  follow §8 rule 0 before every new extraction. Optional future work: add an
  optional `--player-from-folder` flag to `extract_windows.py` that overrides
  `json.playerId` with a folder→UUID mapping read from `metadata/players.csv`,
  removing the manual JSON-patch step.
- `classify_session.swift` is out of sync with the v3 model schema (feature
  names + feature pipeline). Either fix it (rewrite `extractFeatures` and
  switch to descriptive names matching the model spec) or rely on
  `evaluate.py` + the frozen `.mlmodel` for honest baselines per §6.2.1.
- `classify_session.py` hardcodes `_v2_classified.csv` in its output filename.
  Either accept the rename step or add a `--version` flag (one-line change).
- No single script applies a `_validation.csv`'s `corrected_label` column back
  into the session JSON before `extract_windows.py`. Today this is a manual
  one-off Python snippet. Consider adding `scripts/apply_validation.py`.
- `metadata/sessions.csv` is manually maintained. Consider having
  `extract_windows.py` append a row automatically.
- `evaluation_report.md` is manually appended. Consider having `retrain.py`
  write a versioned block automatically.

If the user asks to fix one of these, do it as an isolated PR-sized change —
do not bundle with model training.
